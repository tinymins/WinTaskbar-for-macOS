# System notification capture PoC

独立的 macOS 原生诊断 App。只验证系统通知呈现进程通过 Accessibility 暴露了哪些内容，不接飞书等应用专用 API，不修改 WinTaskbar，不隐藏或点击原生通知。

## 编译

在仓库根目录执行 `bash Prototypes/NotificationCapturePoC/build.sh`。
产物为 `dist/Notification Capture PoC.app`，使用独立 bundle ID 和临时 ad-hoc 签名。
重新编译可能需要重新授予辅助功能权限，不影响正式 WinTaskbar 的签名和权限。

## 手动验证

1. 在 Finder 中打开产物，点击“授权辅助功能”，在 macOS 系统设置中允许此 App。
2. 回到 App，点击“开始读取”。启动 App 本身不会开始扫描。
3. 让任意应用产生一条已知标题和正文的普通系统通知。
4. 检查快照是否包含与真实通知一致的标题、正文和来源描述；只有窗口或 AXRole 不算读取成功。
5. 等原生横幅消失，确认已捕获的内容仍保留在 PoC 窗口中。
6. 点击“停止读取”结束扫描。不要把原始私密内容作为反馈；报告是否读到正文、进程诊断和错误码即可。

结果要分别记录通知中心收起时的新横幅，以及手动打开通知中心后的已有通知；后者成功不代表前者成功。
初次验证可仅使用测试内容，避免验证码等敏感通知。

## 边界

- 每秒尝试扫描两个系统通知 UI 进程的 AXWindows 子树，后台串行执行；未完成时不并发启动下一次。
- 每个进程有 2 秒、800 节点、18 层的遍历预算及单次 AX 消息超时，触及上限会显示诊断。
- 显示 AXRole、AXTitle、AXDescription、AXValue 原始字符串。系统组件、控件文字也可能出现，不自动认定为消息正文。
- 不同快照保存在内存里，没有超时删除；退出 App 后清空。不写文件、标准输出或网络。
- 完全相同的快照只保留一份；一条通知内容变化可能产生多份快照。此 PoC 不验证逐条消息去重、完整捕获率或隐藏通知后的采集。
- 这是捕获可行性验证，不是最终右下角卡片界面。编译和签名检查通过不代表真实通知读取已验证。
